# Independent finding validation (2026-10-12)

Read-only spot-check of the 14 reported findings against their decisive production paths. No source edits or hardware tests. “Accept” means the stated trigger follows from code; static timing/fault cases remain unobserved on a device. I used Matt Pocock's codebase-design vocabulary for interfaces/seams and the Swift concurrency guide for cancellation.

| FW-A9 | **Accept / medium-high, static race** | `protocol.cpp:2631-2639` publishes `c.used=false` under `g_registryMux` before `transport->disconnect(ClientId{i})`. | iOS-1 CloudKit checkpoint | **Accept, scope precision / high** | `CloudKitFaceSync.swift:188-199` decodes each fetched operation before the inner ingest `do` at `:212-221`; recoverable `decode` or `op.validate()` failures (`:393-400`) reach outer `applyFailure` at `:303,347-352`, which sets `halt` but never `checkpointBlocked`. | iOS-2 cancelled group cleanup | **Accept / high for cancellation path** | `BoardGroupCoordinator.swift:797-820` starts per-board `group_start` tasks, then catch calls `abortStartedBoards` in the same producer task at `:843-859`. Cleanup at `:875-898` uses `withOutput` and an inner `try? requestReliable(.stopScroll...)`. The parent task remains cancelled; `BoardConnection.withOutput` at `:175-195` installs a cancellation handler that cancels its child operation, and wire `sendUnqueued` begins with `Task.checkCancellation()` at `:739-740`. The nested `try?` swallows stop failure, then cleanup invalidates the lease (`:896`). Thus a board that already accepted `group_start` can continue. This applies specifically when the *producer task itself* is cancelled; ordinary command failure on an uncancelled producer can send stops. |

## Focused iOS feature/watch addendum

These five candidates were supplied after the core validation. I checked only their relevant paths; no VoiceOver or watch runtime was available.

| Candidate | Verdict / confidence | Decisive evidence and precision notes |
| --- | --- | --- |
| Live lip-sync edit dedup | **Accept / high** | `LipSyncModel.swift:227-240,254-262` edits mapping/costume and refreshes `previewFrame`; `refreshPreviewFrame` at `:296-298` only recomposes the local frame. Tick at `:463-470` returns whenever `lastSentVowel` equals the current phoneme, before sending. The gate changes only on `push` (`:488`) or failure/stop/start paths, so a steady phoneme keeps old board pixels until phoneme changes. The view explicitly permits edits while running (`LipSyncView.swift:33-39`). |
| Preset/video VoiceOver slider seek | **Refine / medium static evidence** | Both `PresetLiveView.swift:314-327` and `VideoPlayerView.swift:359-373` binding setters only update `seekPositionMs`; getter reads `model.positionMs` unless `isSeeking`, and only `onEditingChanged(false)` commits `model.seek`. A value update that does not emit that edit-end callback is discarded. The local Apple Slider reference describes `onEditingChanged` in terms of dragging and VoiceOver changing bound values, but does **not** explicitly guarantee whether VoiceOver sends edit-end callbacks. Therefore the unhandled non-drag path is proven; the specific VoiceOver failure needs a runtime accessibility check or stronger API evidence. |
| Debug refresh after board switch | **Accept with scoped trigger / medium-high** | `DebugViewModel.swift:495-506` clears snapshots when session changes, then calls `refreshOverview`; `:611-618` refuses a new refresh while `isRefreshingOverview` is true. A prior `refreshOverview` holds its original connection through three awaited reads and mutates shared snapshot properties at `:621-664` with no session-key/connection guard. A `.task(id:)` driven prior refresh (`DebugView.swift:70-73`) is cancelled on key change, and `BoardConnection.sendUnqueued:759` checks cancellation after the reply, so that *specific* route is less likely to contaminate snapshots. Blank data until manual refresh remains possible when the old cancelled refresh holds the busy flag during new page appearance. |
| Watch crown echo snap/send | **Accept / high for off-grid echo** | `WatchSessionModel.swift:99-114` applies phone snapshots to draft values outside the two-second touch window. `WatchCrownValueView.swift:102-105` sets `crownValue` from such a value if it differs by at least one step; `:96-100` then treats that programmatic change as crown input, snaps it, writes the binding, and calls the send closure. Brightness uses step 5 (`WatchRootView.swift:186-198`), so a phone brightness of e.g. 83 after crown 50 snaps to 85 and sends 85 without watch input. On-grid echoes (`snapped == value`) do not send; the interval slider can similarly quantize fractional phone values. |
| Debug terminal read-only `get_info` steals output | **Accept / high** | `DebugViewModel.swift:891-918` calls `connection.output.begin(.debug)` for **every** `.cmd`, including its default `monitorInput="get_info"` (`:305`) and catalog query template (`DebugCommandCatalog.swift:54`). `BoardPlaybackCoordinator.swift:47-55` replaces the output lease, cancels old operations, and invokes the previous producer's stop handler.
