# 板端表情库实现与传输优化

实现日期：2026-10-15。设计依据：2026-10-15-board-owned-faces-design.zh-CN.md。

## 已实施

- App 正式保存列表只读取当前已连接板子；断线关闭列表和保存命名窗，离线隐藏保存列表入口。未提交草稿可恢复，恢复与读取本身不发送显示帧。
- 旧本机表情文件保留，提供连接后显式选择迁移。迁移使用与源项和目标板绑定的稳定 ID，原文件不删除。
- 新增先持久化固定 UUID、目标板、提交快照和待确认状态。保存后必须读回内容、名称、类型、部件调用和顺序；结果不明保留原 ID，先核对再重试。确认旧快照不等于当前新编辑也已保存。
- 编辑保持开始编辑时的内容和 boot/gen 基线。仅本会话明确成功的重命名可推进基线；读取他端新版本不会使旧稿获得覆盖权限。
- 固件从 App 同一份部件资源生成只读 92 部件表。精确匹配的部件表情使用版本化编号保存；手绘或部件元数据与像素不符时保存 47 字节位图。旧客户端仍读取完整 frameBytes 投影。
- 所有增量修改与整库导入支持 expectedBootId/expectedGen；新增可要求 createOnly。整库导入在开始和结束都检查版本。
- 完整运行时表先在临时内存中验证、构造，文件原子提交成功后才发布；失败保留旧文件、旧表和当前显示。
- GET_FACES 按版本共用一份有大小上限的 PSRAM 快照，分页不重复访问闪存。App 合并同时读取；同一物理板、同一启动 ID、版本经板子确认未变时复用一份内存读缓存。保存会使之前的读取失效，保存后核对不会复用保存前的下载。
- 闪存载荷读写分为至多 2048 字节一段，段间释放 Storage/HardwareBus 锁并让出调度；打开、关闭、flush、rename 仍持锁。RMT 提交到传输完成全过程与闪存互斥。不能承诺原子提交完全无停顿，但不让闪存操作插入正在输出的 LED 帧。
- 修正 Mac Catalyst 不支持的工具栏 API 调用，以便构建当前源码验收客户端；未改变 App 权限配置。

### 两板大库兼容验收结果

使用原已安装客户端经真实 BLE 对新固件进行验收（不是新版 App 的真实 BLE 通过证明）：

- 两板分别导入包含 11 默认项、59 部件项、58 自定义项的 128 项测试库；逐项核对 ID、名称、类型、顺序、部件调用和完整 47 字节像素均一致。导入期间仍为原 index7、34 灯，accepted=1、queued=0、refreshFail=0；用户目视确认 A 板传输期间正常，没有杂点或闪烁。
- 两板串口 B1 遍历全部 128 项并回绕、B2 返回，核对每项亮灯数；500ms 固件自动轮播也覆盖全部 128 项，期间同时读列表，刷新失败始终 0。
- 遍历脚本的恢复等待条件只按旧 lastReason 判断，曾过早断言恢复失败；修正为等待实际目标 index/像素/interval 后，单独恢复脚本确认两板 index7、34 灯、manual、3000ms。切换与轮播覆盖本身已分别通过，不能把最初整个脚本称作无失败。
- 保持 128 项正常复位，两板均从闪存载入全部 128 项；真实 BLE 重连并重新读取后，128 条导出记录与复位前逐字段一致，未发送额外显示帧。
- 已将两板测试库替换回备份，各自 11 条原记录逐字段完全一致；最终均 index7、34 灯、亮度50、#f971d4、3000ms、manual/idle、queued0、refreshFail0。全部117个临时项已从每板清除。用户随后目视确认“两块都正常”，原有粉色默认表情没有杂点、闪烁或残影。

证据：A/B-bulk-readback.json、A/B-reboot-readback.json、A/B-before/after.json（A 的原始 before 在 /tmp/rina-save-review/transfer-A-before.json）、bulk-cycle.log、cycle-cleanup.log、reboot-128.log、A/B-serial.log。实体灯输出没有外接逻辑分析仪，串口像素计数与保存文件的逐字节核对不能代替电气波形测量。

## 多面板保存目标（后续用户要求）

- 正式表情库没有“本机 / This device”标签；仅显示当前已连接板子的保存内容。旧本机文件仅保留显式复制入口，未保存草稿独立恢复。
- 多板连接时，保存先选择目标：每块板独立开关和“所有已连接面板”开关。默认选当前板，打开选择器后才连接的板不会自动加入。
- 覆盖仅更新源板拥有的原 ID；其他目标板分别创建新副本，不按下标或同名 ID 覆盖另一块板的不同内容。保存本身不发送显示帧。
- 每板独立提交和读回核对，界面分别显示结果；重试跳过已确认目标，沿用未确认目标的原 ID。单板与多板保存互相检查持久化待确认记录，连接数变化不会绕过上次操作另建 ID。
- 断线后的显式重试仅凭已验证物理身份重新绑定；只有地址而未验证身份的连接不允许冒充原板。损坏的恢复记录不会被新操作覆盖。

- 已全部确认的操作也保留结果入口，直到用户明确点击完成；重启若发生在板端确认与编辑器记录之间，不能直接绕过记录另建 ID。完成按钮先等待安全的编辑器采纳尝试；连接载体已变化时不从旧记录推断新的覆盖目标，用户先明确查看结果再结束该操作。
